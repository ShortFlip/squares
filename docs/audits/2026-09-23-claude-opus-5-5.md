### High

```
[High] src/components/game/RoomClient.tsx:303 + src/hooks/useRealtimeRoom.ts:282 + src/lib/game/game-players.ts:39-55 — A bingo whose broadcast is missed is never replayed to anyone.
  Scenario: The winner's channel is in the reconnect backoff window, so channelRef is null and broadcast() silently does nothing. The send result is never checked, and hasClaimed stays true, so the claim is never retried. The banner relies on the broadcast echoing back to the sender (self: true), so no tab shows it, the winner's included. A tab that was asleep misses it the same way, because loadGamePlayers reads `won` and `finish_position` but never calls addWinner. This breaks "a missed bingo announcement is not" tolerated.
  Fix: In loadGamePlayers, addWinner for every won row, ordered by finish_position. Queue or retry broadcasts while the channel is null.  (verified)

[High] src/components/game/RoomClient.tsx:174-194 — Any error reading the player's own game_players row is treated as "no row yet", and the fallback upserts marks: [] and won: false over the existing row.
  Scenario: A player who has already won refreshes, and a network blip fails the .single() select. Their board is wiped, won flips to false, and the leaderboard loses the win. This breaks "losing the whole board is not" tolerated.
  Fix: Only treat PGRST116 (or maybeSingle() returning null with no error) as a missing row, and upsert with ignoreDuplicates: true.  (verified)

[High] src/hooks/useRealtimeRoom.ts:218-230 — The postgres_changes fallback only listens for UPDATE on games, so a new round (an INSERT) is never replayed.
  Scenario: A friend's socket is down when the host hits New Round. On SUBSCRIBED the hook reloads the old gameId, so the friend stays on last round's board and writes marks to the old row. Everyone else sees them as SYNCING for the rest of the round.
  Fix: Subscribe to INSERT on games too, or re-read the room's latest game on SUBSCRIBED.  (verified)

[High] src/hooks/useRealtimeRoom.ts:127 + src/stores/gameStore.ts:156-159 — A presence sync calls setOthers(missingOnly), and setOthers drops every synced entry that isn't in the list.
  Scenario: A friend joins mid-round. Every rail card that had loaded falls back to SYNCING, and the next mark_updated creates entries named "Player" with an empty card.
  Fix: Add an addPlaceholders action that merges placeholders in, and use it from presence.  (verified)

[High] src/components/game/RoomClient.tsx:341 + :94-100 — The next round number comes from the local store, and the reconnect read orders by round_number. games has no unique (room_id, round_number).
  Scenario: After End Night the host refreshes on Game Over, where the reconnect effect doesn't run, so roundNumber is null. Play Again inserts a second "round 1". A player who refreshes later can load the old finished round instead of the live one.
  Fix: Work out the round number from the database, order the reconnect read by started_at, and add a unique constraint.  (verified)

[High] src/components/game/GameView.tsx:238, 340-351 — The game screen needs about 784px of height, but the root is h-screen overflow-hidden and the grid is a fixed 608px.
  Scenario: A browser maximized on a 1280×800 display gets roughly 670px of viewport. The fixed parts add up to header 56 + body padding 40 + panel padding 36 + name row about 30 + gap 14 + grid 608. The bottom row of squares is clipped and can't be scrolled to, so columns and diagonals can't be completed. This breaks "~1280×800 minimum" and "board never shrinks below a markable size".
  Fix: Size the grid as min(608, available height minus chrome), or add a compact layout below about 790px of height.  (the code is verified; the viewport height is an estimate)

[High] supabase/migrations/20260410000000_initial_schema.sql:157-159 + src/components/game/ProfileModal.tsx:84-100 — An extension of decision 0002: players can be read by anyone, so every player's claim_code and browser_id is public.
  Scenario: Anyone with the anon key requests /rest/v1/players?select=claim_code and enters a friend's code in Profile, then Claim. They are now that friend, with the friend's history and wins. The anon key ships in the public bundle.
  Fix: Serve players through a view that leaves out claim_code and browser_id, and do the claim lookup in a security-definer RPC.  (verified)
```

## Strengths

- `buildGameSetup` gives all three round-start paths one item filter and one call list, so the card and the call list can't drift apart. The item-pool and shuffle tests pin this down.
- DESIGN.md's invariants are real in code: SYNCING never shows 0/25, the win banner sits in the page flow instead of covering the board, and HostControls is one shared component.
- User-facing errors are always generic toasts. There is no `dangerouslySetInnerHTML`, and git history is free of secrets.
- The realtime hook guards its async continuations with a `cancelled` flag, clears its timers, and never moves the call count backwards.

## Ideas (value for effort, highest first)

1. **Discord webhook** (S): post "X got bingo — Column 2" and an end-of-night recap to the channel. Everyone is already in Discord.
2. **Match-point cue** (S): a soft tick and a pulse on a rail card when that player is one away. It builds tension without stealing focus.
3. **Compact layout for short windows** (S): this also fixes the 800px-height High.
4. **Night recap on Game Over** (M): fastest bingo, most near-misses, the MVP. A post-match scoreboard.
5. **Season standings** (M): 3 points for 1st and 1 for 2nd, across nights. It gives the recurring night some stakes.
6. **Walk-up fanfare picker** (S): each player chooses their own bingo sound in Profile.
7. **Squad-called hint** (M): when rivals mark an item that's also on your card, the square glows faintly. Honor mode starts correcting itself.
8. **Per-game card packs** (S): CoD and Rocket League templates, with a "last used" quick pick.
9. **Forced socket-drop harness** (S), from Next Up: finally proves the reconnect backoff against a real dropped socket.
